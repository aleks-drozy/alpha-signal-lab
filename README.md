# alpha-signal-lab

Does gradient boosting on standard price/volume features add predictive
power over plain momentum, under leakage-proof evaluation?

This repo is a pre-registered, leakage-audited test of whether a LightGBM
regressor on 12 standard price/volume features predicts 5-day
cross-sectional excess returns better than two naive baselines (12-1
momentum, equal-weight buy-and-hold), on free daily US equity data. The
product here is the methodology and audit harness, not a claimed alpha: the
pre-registered success criterion is stated before any result is shown, and a
null result is reported as a null result.

Pre-registered spec: [`specs/methodology.md`](specs/methodology.md) (frozen
2026-08-03, not edited after results exist).
Full results write-up: [`REPORT.md`](REPORT.md) (auto-generated by
`report.py`, real numbers or TBD if the pipeline hasn't run yet).
Live dashboard: [`docs/index.html`](docs/index.html) (static, no backend,
open directly or serve via GitHub Pages).

## Pre-registered success criterion

```
mean(daily rank IC) > 0.02   AND   Newey-West t-stat(daily rank IC) > 2.0
```

on the honest (purged walk-forward) out-of-sample predictions. Both
conditions must hold. Anything short of that is reported as NULL, not
reframed as a near-success.

## Quickstart

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt

python -m alpha_lab.run_all   # ingest -> features -> model -> evaluate -> leaky_twin -> explain -> report
```

`--refresh` re-downloads raw data even if a cache exists:

```bash
python -m alpha_lab.run_all --refresh
```

Run the leakage audit alone (no network calls, uses the committed fixture
panel in `tests/fixtures/`):

```bash
pytest tests/test_leakage_audit.py -v
```

## Repo structure

```
specs/methodology.md        pre-registered spec, frozen before results existed
src/alpha_lab/
  config.py                 single source of truth for every frozen parameter
  ingest.py                 Stooq primary / yfinance fallback OHLCV fetch, manifest + cross-check
  features.py                point-in-time features, labels, cross-sectional rank transform
  cv.py                      PurgedWalkForward: purge + embargo + expanding window
  model.py                   per-fold LightGBM fit/predict, fixed hyperparameters
  evaluate.py                rank IC, Newey-West t-stat, decile spread, equity curves, baselines
  leaky_twin.py               naive shuffled 5-fold CV control (the leakage floor/ceiling reference)
  explain.py                  SHAP: beeswarm, importance bar, local waterfalls, fold-stability heatmap
  report.py                   fills REPORT.md, writes docs/results.json for the dashboard
  run_all.py                  orchestrator: runs every step above in order
tests/
  test_leakage_audit.py       the 8 pre-registered leakage audits, writes docs/badges.json
  test_features.py            unit tests for individual feature formulas
  test_cv.py                  PurgedWalkForward boundary math
  test_ingest.py              ingestion tests against a committed synthetic fixture, no network
docs/
  index.html                  static dashboard, reads docs/results.json + docs/badges.json
  img/                        SHAP plots written by explain.py
.github/workflows/ci.yml      pytest on push, fixture-only, no live network calls
```

## Honest results

See [`REPORT.md`](REPORT.md) for the full write-up with real numbers (or the
[dashboard](docs/index.html) for the interactive version). Summary: the
verdict line at the top of both states PASS or NULL against the criterion
above, plainly, before any supporting chart.

## What this deliberately does not do (v2 / deferred scope)

- **Point-in-time universe.** The 30-name universe is hand-picked as "liquid
  since 2010," which is survivorship bias we can observe today; a real
  point-in-time index membership feed is out of scope for v1.
- **Multiple horizons.** Only H=5 is tested. Sweeping 1/10/21-day horizons
  with the same pre-registration discipline is deferred.
- **CPCV.** A single walk-forward path is used, not combinatorial purged
  cross-validation, so there is no distribution over OOS Sharpe.
- **Hyperparameter search.** LightGBM parameters are frozen a priori. This
  closes an obvious leakage vector but is not a best-effort model.
- **Other asset classes.** No futures, FX, or non-US equities.
- **Live cron / paper trading.** This is an offline research pipeline, not a
  running signal generator.
